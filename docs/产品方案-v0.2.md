## 0. 一页结论

**一句话定位**
> 不是又一个 AI 聊天框，而是把每一次"我看懂了"自动变成"我记住了、我今天该做什么"的个人学习工作台。

**要解决的问题**
通用大模型能讲清楚线代题、能改英语作文，但**讲完就散了**：下次对话从零开始，没有复习、没有沉淀、没有日程。而 Anki/待办类工具反过来——记得住、排得开，但要人肉制卡、跟学习内容完全脱节。中间缺一个"把输入自动转成学习资产"的东西。

**核心闭环**
```
输入 ──► 理解 ──► 固化 ──► 复习 ──► 计划 ──► 复盘
问/拍/贴   讲/图/追问   卡片/题/笔记   FSRS    DDL 倒排   周报
  ▲                                                 │
  └─────────────────────────────────────────────────┘
```

**三个差异化（也是 MVP 的验收点）**
1. **对话即入库**：任何回答都能一键（或由 Agent 主动建议）变成卡片、题目、笔记、待办——不需要复制粘贴到别的 App。
2. **今日一张纸**：左侧点"今日"，一屏只有"复习 24 张（约 9 分钟）+ 今天 3 件事 + 考试倒计时"，点一下开始，结束后有记录。
3. **能干活的 Agent，而不是会聊天的模型**：工具调用可见、可中断；检索有页码引用；**所有写入可撤销**。

**MVP 边界（6 周，每周 10–15 小时）**
- 做：多模态对话、资料库（PDF/PPT/DOCX + 图片）、带引用的问答、卡片生成 + FSRS 复习、今日待办、自然语言排计划、科目空间、用量统计。
- 不做：题库商城、社交、直播课、多用户/班级、全自动"替我听讲"、知识图谱可视化（P2）。

**技术路线（一句话）**
Web-first 单体应用：Next.js 16 + React 19 + TypeScript + SQLite，模型走 OpenAI 兼容层（默认 DeepSeek），先本机跑通，再用 Tauri 2 套壳成桌面 App。

**界面（一句话）**
打开就是和 Agent 的对话；左边一列功能入口（对话 / 今日 / 复习 / 资料 / 科目 / 统计），点哪个进哪个，不做仪表盘首页。

**成本**
按每天 30 轮对话 + 20 次生成估算，**约 ¥10–20/月**（DeepSeek 缓存命中价，见 7.10）。

**周期**
M0–M5 共 6 周出可用版本；W7–W10 补练习/批改/周报。

## 1. 背景：我真实的一天

| 时间 | 场景 | 现在怎么做 | 不爽在哪 |
|---|---|---|---|
| 07:40 | 起床后 10 分钟 | 刷手机，偶尔翻 Anki | 卡片是几周前手动加的，早就不对应最近学的内容 |
| 10:00 | 线代课/自学 | 拍题问 AI | 讲得挺好，但**没有存下来**；下次遇到同类题还是问一遍 |
| 13:00 | 午休 | 想复习，但不知道复习什么 | 没有到期队列，全凭感觉 |
| 20:00 | 学 AI（看论文/课程） | 一边看一边问，开 5 个会话 | 会话散落，概念没串起来；术语记不住 |
| 22:30 | 英语 | 写作文发给 AI 改 | 改了就看一眼，生词不复习，下次还错 |
| 周日 | 计划下周 | 手写待办 | 计划和学的内容、复习量完全脱节 |

**三个科目的共同点**：都需要"理解 → 练习 → 记忆"；不同点只是**产物形态**不同（AI 是概念/代码，线代是公式/推导，英语是词汇/句式/作文）。这决定了产品应该是"一个通用闭环 + 三套科目模板"，而不是三个独立 App。

### 2.2 商业产品的参照

- **ChatGPT / Claude / 豆包 / Kimi**：问答和文件理解最强，但记忆是"产品级黑盒"，不给你复习队列与学习计划。
- **NotebookLM**：资料溯源做得最好，但本质是"读"，不是"练"和"记"。
- **Anki / Quizlet**：记忆科学最扎实，但制卡成本高、内容生成靠人。
- **Khanmigo / Duolingo**：教学法与激励设计值得学（苏格拉底式提问、streak、每日目标），但封闭且不接你的教材。
- **得到 / 学习通**：课程体系完整，但与自己的材料、自己的 AI 无关。

### 2.3 三条路线，以及为什么建议自研

| 路线 | 做法 | 优点 | 代价 |
|---|---|---|---|
| A. 直接用 | 跑 [DeepTutor](https://github.com/HKUDS/DeepTutor) 或 [deep-student](https://github.com/helixnow/deep-student)，填 API key | 10 分钟能用，功能远超 MVP | 不贴合自己的科目与习惯；改不动；**学不到东西** |
| B. 组合 | Cherry Studio + Anki + 滴答清单 + NotebookLM | 每项都是最强的 | 资产割裂，没有自动闭环，每天在 4 个 App 间搬运 |
| C. 自研 | 做"闭环"这一件事，其他都接现成 | 贴合、可迭代、练手 AI 工程 | 6 周投入 |

**建议：以 A 作为"目标态体验"（先 `docker run` 跑一遍 DeepTutor，感受一下成熟形态），以 C 为主线，但严格砍到只做闭环。** B 可以作为过渡期方案。

> 提醒：自研的最大风险不是技术，是**范围膨胀**。DeepTutor 有 42k star、几十人维护、功能覆盖极广；你的优势是"只服务一个人"，所以每个功能都要问一句"这周会用吗"。

## 3. 产品定义

### 3.1 目标用户

| 维度 | 描述 |
|---|---|
| 主用户 | 你：大学生，自学 AI / 线性代数 / 英语，每天 1–2 小时，Windows 桌面为主 |
| 使用环境 | 桌面端深度使用（长文、PDF、代码、多窗口），手机端碎片复习（等车、睡前） |
| 技术水平 | 能配 API key、能跑 `npm`；愿意接受"先能用再好看" |
| 核心诉求 | 学得进去、记得住、知道下一步做什么；不想在工具间搬运 |
| 反诉求 | 不要社交、不要打卡攀比、不要复杂配置、不要被 AI 代替思考 |

### 3.2 定位

> **个人 AI 学习工作台（Study Cockpit）**：以对话为入口，以"卡片 / 题目 / 笔记 / 任务"为资产，以"今日"为节奏控制器。

界面与服务对应三层：
- **主界面 = 对话**：打开就是和 Agent 聊天（文字 / 图片 / 文件 / 语音），永远不离开这一屏
- **左侧列表 = 其他功能**：今日、复习、资料、科目、统计，点一下右侧切换
- **对话的产物 = 资产**：卡片、题目、错题、笔记、资料（可检索、可导出、可复习）

### 3.3 六条设计原则

1. **对话是入口，资产是结果。** 每个回答下方永远有 4 个动作：生成卡片 / 出题 / 存笔记 / 加任务。Agent 在合适时机主动建议一次，不打扰。
2. **先回忆，再解释。** 默认"苏格拉底模式"：先问你怎么想，再给提示，最后给完整解答（可一键展开）。看答案 ≠ 学会。
3. **一切可溯源。** 回答标注来源（资料名 + 页码）；卡片记录来源与生成时间；模型与耗时可见。不可溯源的内容明确标注"来自模型常识"。
4. **写入必须可撤销。** Agent 改数据（建卡、改任务、写笔记）都以事务执行，顶部出现"已创建 5 张卡片 · 撤销"。
5. **本地优先，数据可带走。** SQLite 单文件 + 附件目录；支持导出 Markdown / APKG / JSON；不做账号体系。
6. **对话是首页，不铺仪表盘。** 打开就是对话框，功能收进左侧列表；"今日"只推 3 件事，不做信息流、不做排行榜。

### 3.4 核心闭环（产品的心脏）

| 环节 | 用户动作 | 产品动作 | 沉淀物 |
|---|---|---|---|
| 输入 | 提问 / 拍照 / 拖文件 / 划词 | 解析 + 检索 + 路由模型 | 消息、附件 |
| 理解 | 追问、要例子、要图 | 分层讲解、图示、代码、反例 | 笔记 |
| 固化 | 点"生成卡片"/"出题" | 结构化生成 + 去重 + 入库 | 卡片、题目 |
| 复习 | 每天 5–10 分钟过卡 | FSRS 调度、4 键评分、遗忘预警 | 复习日志 |
| 计划 | "12/20 考线代" | 倒排里程碑 → 每日任务 | 计划、待办 |
| 复盘 | 周日看一眼 | 汇总薄弱点、给出下周建议 | 周报 |

**判断一个功能该不该做：它是否让这个环转得更快？** 不能的，砍掉。

| AI | 概念分层讲解、术语卡 | 论文精读模式、代码实验片段 | 本地代码沙箱、论文库检索 |
| 统计 | 用量/成本、连续天数 | 周报、留存率、科目时长 | 年度报告 |
| 数据 | SQLite、导出 Markdown/JSON、备份 | APKG 导出、WebDAV 同步 | 端到端加密云同步 |

### 4.2 对话与 Agent（核心，P0）

**输入形态**

| 形态 | 交互 | 技术 | P |
|---|---|---|---|
| 文本 | 输入框，Shift+Enter 换行 | — | P0 |
| 图片 | 粘贴 / 拖拽 / 截图快捷键 / 手机拍照上传 | 多模态模型直读（DeepSeek Flash 已支持视觉） | P0 |
| 文件 | 拖入 PDF / DOCX / PPTX / MD，显示解析进度 | 本地解析 → 分块 → 索引 | P0 |
| 划词 | 资料阅读页选中文本 → "问这段" | 选区 + 上下文 | P1 |
| 语音 | 按住说话 → 转写后发送 | ASR（可选） | P1 |

**三种对话模式**（会话级切换，影响系统提示词与工具集）

| 模式 | 行为 | 适用 |
|---|---|---|
| 答疑（默认） | 直接给答案 + 推导 + 一个自测题 | 赶时间、卡住时 |
| 苏格拉底 | 先反问 → 给提示 → 逐步逼近，答案默认折叠 | 想真正学会 |
| 精读 | 按段落/页码讲解资料，逐段提问，产出术语卡 | 论文、教材 |

**Agent 的可视化**（这是"Agent 感"的来源，也是与普通 chat 的分水岭）

```
● 检索《线性代数及其应用》p.182–186 · 0.8s
● 调用 math_check 验证特征值 · 1.2s
● 生成 4 张卡片 → 已加入复习队列      [撤销]
─────────────────────────────────────
特征值就是……（正文）
来源：[线代教材 p.183] [课堂笔记 10/15]
```

- 每一步都能点开看参数与结果；执行中可"停止"；写入类工具执行前有轻量确认（可在设置里关掉）。
- 一次回答最多 6 轮工具调用，超时/超预算自动收敛并说明原因。

**工具清单（P0）**

| 工具 | 作用 | 写入 |
|---|---|---|

**回答的标准结构**（提示词约束，保证可用性）

### 4.4 复习（P0）

- 算法：**FSRS**（`ts-fsrs`，默认参数即可，积累 200+ 条复习日志后可优化参数）。
- 卡片类型：问答、填空（完形）、公式、选择、图片遮挡（P1）。
- 交互：空格翻面 → 1/2/3/4 评分（重来/困难/良好/简单）→ 显示下次间隔；支持"解释一下"（现场调 AI 讲这张卡）、"编辑"、"暂停"。
- 防作弊：翻面前不显示答案；连续"简单"会被提示是否降低难度。
- 来源：每张卡记录 `source_ref`（资料 + 页码 / 会话 + 消息 id），可回跳。
- 统计：今日/本周复习量、留存率（30 天后仍记得的比例）、按科目分布。

### 4.5 练习与错题（P1）

| 写作 | rubric（四六级/雅思）+ 逐句标注 + 改写 |

## 5. 关键流程

### 流程 A：拍一道线代题（最高频）

1. 打开 App（默认对话），`Ctrl+V` 粘贴截图 / 按截图快捷键。
2. Agent：`识别题目 → 检索教材相关页 → 分步讲解`，步骤时间线可见。
3. 回答给出：结论、推导、几何解释、易错点。
4. 用户点"出 2 道变式题"→ 做完 → 批改 → 错的那道进错题本。
5. 用户点"生成卡片"→ 4 张卡入队（含来源页码），顶部提示可撤销。
6. 第二天早上，"今日"显示"复习 4 张 · 约 2 分钟"。

**成功标准**：从拍照到卡片入库 ≤ 60 秒，全程不离开一个界面。

### 流程 B：把一章讲义变成复习资料

1. 拖入 `chapter3.pdf` → 解析（约 30 秒，显示页数与公式数）。
2. 输入："帮我把这一章整理成复习资料，重点在特征值。"
3. Agent 计划：`读目录 → 分节摘要 → 提取 12 个概念 → 生成 20 张卡 → 出 8 道题 → 建 3 个任务`，逐步执行。
4. 完成后给一张"产物卡"：笔记 1 篇、卡片 20 张、题目 8 道、任务 3 个，全部可点开。
5. 不满意可"重做这部分"（只重跑某一步）。

**成功标准**：一份 40 页 PDF → 可复习的资产包 ≤ 3 分钟，且每张卡都能跳回原文。

### 流程 C：英语作文批改

1. 拍照/粘贴作文 → 选择"四级作文"rubric。
2. 输出：总分 + 分项（内容/结构/语言）+ 逐句标注（红色错误、蓝色升级建议）+ 参考范文。
3. 点"生词/好句入卡"→ 自动生成 6 张卡（含例句与发音）。
4. 点"加入今日任务：重写一遍"→ 明天提醒。

### 流程 D：排考试计划

1. 输入："12 月 20 日考线代，我每天大概能学 1.5 小时，现在到第三章。"
2. Agent 反问 2 个问题（每周哪几天没时间？目标是及格还是 85+？）。
3. 生成计划：4 个阶段、12 个里程碑、每日任务（自动避开已排的英语/AI 任务）。
4. 写入后显示甘特图预览，可拖拽调整，调整后自动重排后续。

## 7. 技术方案

### 7.1 总体架构

```
客户端    React 19 + Tailwind 4 + shadcn/ui + Zustand + TanStack Query
          对话流 / 消息动作条 / 今日 / 复习 / 资料阅读器 / 统计
          渲染：react-markdown + KaTeX + Shiki + PDF.js
             │ HTTP / SSE（本机或局域网）
             ▼
服务端    Next.js 16（App Router · Route Handlers · Node runtime）
          ├─ Agent 运行时（工具循环 / 审批 / 撤销 / 长任务）
          ├─ 检索 RAG（解析 / 分块 / 嵌入 / 混合召回）
          ├─ 复习调度（ts-fsrs）
          ├─ 计划与统计（倒排 / 聚合 / 用量）
          ├─ 模型网关（Provider Registry / 重试 / 计费）
          └─ 文档解析（unpdf / mammoth / 多模态 OCR）
             │
             ▼
数据层    SQLite（元数据 + FTS5 + sqlite-vec 向量）/ 本地附件目录 / 迁移脚本
             │ HTTPS
             ▼
模型      DeepSeek flash / v4-pro（默认）
          Qwen / GLM / Kimi / OpenRouter（可选）· Ollama（本地，可选）
```

### 7.2 形态决策

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. Web（Next.js，本机跑）** | 迭代最快、随时能用手机访问、部署简单、无 Rust 工具链 | 要开着终端/服务；截图快捷键弱；像"网站" | ✅ **MVP 选它** |
| B. Tauri 2 套壳 | 安装包小（~10MB）、原生快捷键/托盘/通知、可离线 | 需 Rust 环境；Next.js 需静态导出或 sidecar | ✅ **M5 再套**（前端代码复用） |
| C. Electron | 纯 JS，最省心 | 150MB+、内存高、启动慢 | ❌ |
| D. 纯静态 SPA + 直连 API | 无后端、部署到 Vercel 即可 | API key 暴露在浏览器、无本地文件/索引、无 SQLite | ❌（除非只做 demo） |

> 结论：**先 Web 单体，后 Tauri 套壳**。开发期 `pnpm dev`，日常用 `pnpm build && pnpm start` 或 Docker 一条命令；M5 用 Tauri 把同一套前端打包成桌面 App，服务端作为 sidecar 或改为本地 Rust 命令。

### 7.3 技术栈

| 层 | 选型 | 版本（2026-10） | 理由 |
|---|---|---|---|
| 框架 | Next.js（App Router） | 16 | 前后端一体，Route Handler 做 SSE 很顺 |
| UI | React + TypeScript | 19 / 5.x | 生态最大 |
| 样式 | Tailwind CSS + shadcn/ui | 4 | 快速出好看的界面 |
| 状态 | Zustand + TanStack Query | — | 本地 UI 状态 / 服务端缓存分离 |
| 渲染 | react-markdown + KaTeX + Shiki | 0.19 | 公式与代码块是刚需 |
| 数据库 | SQLite（better-sqlite3）+ Drizzle ORM | 0.45 | 单文件、零运维、可备份、可迁移 |
| 向量 | sqlite-vec | — | 与 SQLite 同进程，无需外部服务 |
| 全文 | SQLite FTS5（中文先分词再入库） | — | 混合检索的另一半 |
| Agent | Vercel AI SDK 7（streamText + tools） | 7.0 | 流式与工具调用开箱即用，不引入重型框架 |
| 模型 | DeepSeek（默认）+ OpenAI 兼容任意家 | — | 国内可直连、便宜、支持视觉与工具调用 |
| 复习 | ts-fsrs | 5.4 | 成熟实现，省掉算法调试 |
| 解析 | unpdf / pdf.js、mammoth、pptx 解析 | — | 纯 JS，免 Python 依赖 |
| 嵌入 | transformers.js + bge-small-zh（本地）或 API | — | 默认本地零成本，可切 API |
| 桌面 | Tauri 2 | 2.12 | 后期打包 |

**明确不用**：LangChain / LlamaIndex（抽象太重，调试困难）、Electron、Postgres、Redis、任何需要 Docker 才能跑的基础设施。

### 7.4 模型接入与路由

统一走 **OpenAI 兼容协议**，Provider 配置存本地（key 加密后存 SQLite 或系统钥匙串）。

| 任务 | 默认模型 | 备选 | 理由 |
|---|---|---|---|
| 日常问答、卡片生成、出题 | `deepseek-flash` | Qwen-Flash、GLM-Air | 便宜、快、支持视觉与工具 |
| 难题推导、证明、代码 | `deepseek-v4-pro` | Qwen-Max、Claude | 推理强（注意：v4-pro 不支持视觉） |
| 图片/公式识别 | `deepseek-flash`（视觉） | Qwen-VL、GLM-4V | 省一次额外调用 |
| 批改/评分 | `deepseek-flash` + 低温度 | — | 稳定输出 JSON |
| 嵌入 | 本地 bge-small-zh | 阿里/硅基流动 API | 零成本、隐私 |

**成本控制**

1. **前缀缓存**：系统提示词 + 科目画像 + 资料片段放在最前且保持稳定，利用 DeepSeek 自动缓存（命中价约为未命中的 1/50）。
2. **按需检索**：不把整本书塞进上下文，检索 3–6 个片段（约 2–4k token）。
3. **预算闸门**：设置每日/每月上限，达到 80% 提示，100% 降级到 flash 或只读模式。
4. **用量面板**：按会话/科目/模型统计 token 与费用，随时可见。

### 7.5 Agent 运行时

- **循环**：`用户消息 → 组装上下文 → 模型 → 若有 tool_call 则执行并回填 → 再循环（≤6 轮）→ 最终回答`。用 AI SDK 的 `streamText` + `tools` + `stopWhen`。
- **上下文装配顺序**（对缓存友好）：
  1. 系统提示词（人格 + 规则 + 输出结构）
  2. 科目画像与偏好（稳定，少变）
  3. 资料片段（检索结果，带页码）
  4. 最近 N 轮对话（滑动窗口 + 摘要）
  5. 本轮用户输入与附件
- **写入事务**：所有写工具返回 `changeSet`，服务端在一个事务里落库并记录 `undo_token`；前端显示"已创建 X · 撤销"，撤销即回滚。
- **审批**：删除类、批量类（>10 条）、涉及计划的写操作需要确认；其余直接执行并提示。
- **长任务**：>10 秒的任务（整章处理）转后台 job，前端显示进度，完成后通知；离开页面不中断。
- **失败处理**：工具失败 → 重试 1 次 → 仍失败则告诉用户哪一步失败、已完成什么，不假装成功。

### 7.6 检索（RAG）

```
文件 → 解析（版面/公式/表格）→ 清洗 → 结构感知分块（按标题/页，300–600 token，10% 重叠）
     → 嵌入（本地 bge-small-zh）→ 写入 chunk 表 + vec 表
查询 → 查询改写（可选）→ 向量 Top-20 + FTS Top-20 → RRF 融合 → 重排（可选）→ Top-5
     → 组装进上下文（带 material_id / page / chunk_id）
```

- **引用**：每个片段带 `material_id + page + 起止字符`，回答里用 `[1]` 标注，前端映射到可点击的原文位置。
- **降级**：嵌入不可用时退化为 FTS + 标题匹配；资料很小时（<30k token）可直接整篇入上下文（有缓存时很便宜）。
- **不做的**：GraphRAG、多级摘要、复杂 rerank 模型——个人语料用不上。

### 7.7 复习调度

- `ts-fsrs` 默认参数；卡片状态（`due / stability / difficulty / reps / lapses / state`）全部落库。
- 每日队列 = 到期卡 + 新卡（新卡上限可配，默认 15）+ 逾期卡（上限 20）。
- 评分 4 键映射 `Again / Hard / Good / Easy`；记录 `review_log` 便于日后优化参数。
- 卡片可"暂停"（不参与调度）与"重置"（重新学）。

### 7.8 数据模型（核心表）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `subject` | id, name, goal, exam_date, daily_minutes, color | 科目 |
| `profile` | id, subject_id, kind, content, confidence, evidence_msg_id | 画像/偏好，可按条编辑删除 |
| `material` | id, subject_id, title, type, path, hash, pages, status | 资料 |
| `chunk` | id, material_id, page, text, tokens | 分块 + 向量（vec0 虚表） |
| `conversation` | id, subject_id, title, mode, model, pinned | 会话 |
| `message` | id, conversation_id, role, content_json, model, usage, refs_json | 消息（含工具步骤） |
| `card` | id, subject_id, type, front, back, tags, source_ref, fsrs_state… | 卡片 |
| `review_log` | id, card_id, rating, reviewed_at, elapsed_ms, scheduled_days | 复习日志 |
| `question` / `attempt` | 题干、答案、rubric / 作答、得分、错因、feedback | 练习与错题 |
| `task` | id, subject_id, title, due, estimate_min, status, plan_id, repeat | 待办 |
| `plan` | id, subject_id, exam_date, milestones_json | 计划 |

### 7.9 工程难点与解法

| 难点 | 解法 |
|---|---|
| 中文 PDF 解析乱序 | 优先用带版面的解析（unpdf 的 layout 模式 / 可选 MinerU 服务）；解析质量差的文件提示用户 |
| 公式渲染 | KaTeX；模型输出约束为 `$...$` / `$$...$$`；渲染失败回退纯文本 |
| 图片题识别错 | 让模型先复述题目再解答（"先确认我理解对了吗"），错可纠正 |
| 流式 + 工具调用并存 | AI SDK 的 `fullStream` 区分文本增量与工具事件，前端分区渲染 |
| 长会话 | 超过 20 轮自动摘要为"会话记忆"，提示词里带摘要 |
| 卡片重复 | 生成前用向量相似度查重（>0.9 跳过），并提示"已存在相似卡片" |
| 数据备份 | 一键导出 `loop-backup-YYYYMMDD.zip`（SQLite + 附件 + 配置）；支持自动每日备份 |
| 移动端访问 | 局域网内 `http://<PC-IP>:3000` 直接可用；P1 做 PWA + 响应式 |
| API 变更/涨价 | Provider 抽象层 + 模型别名映射，换模型只改配置 |

## 8. 路线图（每周 10–15 小时）

| 里程碑 | 周 | 交付 | 验收标准（做到了才算完） |
|---|---|---|---|
| **M0 骨架** | W1 | 项目脚手架、Provider 设置、流式对话、会话列表、Markdown/KaTeX、SQLite 落库 | 能连续对话 20 轮，刷新不丢；断网/报错有提示 |
| **M1 多模态 + 资料** | W2 | 图片粘贴/拖拽、PDF/DOCX/PPTX 解析、分块索引、检索、引用跳转、资料库页 | 传一份 40 页讲义，问"第 3 节讲了什么"能答对并给出页码，点击可跳转 |
| **M2 卡片 + 复习** | W3 | 卡片生成/编辑、FSRS 调度、复习页、来源回跳、每日上限 | 生成 20 张卡，次日"今日"出现到期队列，能完成复习并正确排期 |
| **M3 今日** | W4 | 今日页、待办 CRUD、DDL 倒计时、专注计时、复习队列整合 | 打开就是今天要做的 3 件事 + 复习入口，一键开始/结束有记录 |
| **M4 计划 + 画像** | W5 | 自然语言排计划、任务生成、科目画像 v1、动作条、"对话即入库" | 说"12/20 考线代，每天 1.5h"，生成可执行计划并落到每日任务 |
| **M5 打磨** | W6 | 撤销、统计/用量、导出/备份、快捷键、空状态、Tauri 打包（可选） | 连续用 7 天不别扭；数据能一键备份与恢复 |
| **P1 练习** | W7–8 | 出题、批改、错题本、变式题 | 做完一套 10 题，错题进本并能两周后重做 |
| **P1 英语 + 周报** | W9–10 | 作文批改、生词入卡、周报、薄弱点 | 一篇作文 → 6 张卡 + 1 个重写任务；周报能指出 3 个薄弱点 |

**每个里程碑结束都真实使用 3 天再进入下一个**——这是最容易被跳过、也最影响成败的一步。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **幻觉**：讲错题、编造引用 | 学错知识，最致命 | 强制引用 + "资料中没有就说没有"；数学用 sympy 校验；提供"这答案有问题"一键反馈并记录 |
| **范围膨胀** | 6 周做不完，最后什么都不好用 | 严格按第 11 节"不做清单"；每个功能先问"这周会用吗"；P2 一律延后 |
| **复习负担反噬** | 卡片堆积 → 放弃 → 全盘弃用 | 每日上限 + 只生成高价值卡（定义/易错/公式）+ 一键"清空积压" |
| **生成卡片质量差** | 复习浪费时间 | 卡片模板约束 + 生成后预览可批量删 + 用 30 天后留存率反推质量 |
| **成本失控** | 不敢用 | 预算闸门 + 用量面板 + 默认 flash + 缓存 |
| **解析失败**（扫描件/加密 PDF） | 资料用不了 | 明确报错原因 + 提供"截图提问"替代路径 |
| **模型/API 变更** | 功能挂掉 | Provider 抽象 + 多 provider 兜底 + 不在代码里写死模型名 |
| **数据丢失** | 几周成果没了 | 每日自动备份 + 一键导出 + 数据目录不在系统盘 |
| **隐私** | 学习记录外泄 | 数据全本地；只把必要片段发给模型 API；明确"什么时候数据离开本机" |
| **只做不用** | 最大风险 | 每个里程碑后强制自用 3 天；连续 7 天不用就砍功能，不加功能 |

## 10. 度量（个人自用版）

不看 DAU/留存这些产品指标，看**学习效果**：

| 指标 | 目标 | 怎么算 |
|---|---|---|

## 附录 B · 提示词与结构化契约要点

**系统提示词骨架**（约 400 字，稳定前缀利于缓存）

```
你是「回路」的学习助手，服务一名中国大学生，科目：{subject}。
学生画像：{profile}
原则：
1. 先给结论，再给推导；公式用 $...$，多行用 $$...$$
2. 优先使用检索到的资料；资料没有依据时明确说"以下来自模型常识"
3. 数学/计算类结论必须可验证，不确定时说不确定
4. 回答末尾给 1 道自测题（折叠答案）
5. 不要主动编造页码或引用；引用格式 [资料名 p.页码]
6. 面向初学者：先直觉，再形式化
```

**卡片生成契约**（模型输出 JSON，zod 校验）

| 字段 | 说明 |
|---|---|
| `type` | qa / cloze / formula / choice |
| `front` / `back` | 正面 / 背面（KaTeX） |
| `tags[]` | 概念标签，用于聚合薄弱点 |
| `source_ref` | material_id + page，或 message_id |
| `difficulty` | 1–3，影响初始 FSRS 参数 |

**批改契约**：`score`、`rubric_items[]`（每项得分/满分/理由）、`errors[]`（原文片段、类型、修改建议）、`rewrite`。

**计划契约**：`phases[]`（阶段/起止/目标）、`milestones[]`、`tasks[]`（日期/标题/时长/依赖）。
