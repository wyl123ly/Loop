# 自动更新

## 发布约定

- 仓库：`https://github.com/wyl123ly/Loop`
- Release tag：`v0.3.1`（语义版本，带 `v` 前缀）
- Release 附件：固定命名 **`Loop-Desktop-win64.zip`**
- ZIP 根目录必须包含：
  - `Loop.exe`
  - `version.json`，内容如 `{"version":"0.3.1"}`
- `version.json` 由 `packaging/build_native.ps1` 从 `app/pubspec.yaml` 自动生成。

发布新版本时：

1. 修改 `app/pubspec.yaml` 的 `version` 和 `app/lib/update/app_version.dart` 的 `AppVersion.current`，两者保持一致。
2. 运行 `packaging\build_native.ps1`，得到 `release\Loop-Desktop-win64.zip`。
3. 在 GitHub 创建 Release，tag 填 `vX.Y.Z`，上传该 ZIP，填写更新说明。
4. 本地客户端启动或点「检查更新」时，会读取 GitHub 最新 Release。

## 客户端流程

1. `GET /repos/wyl123ly/Loop/releases/latest`
2. 选择 `Loop-Desktop-win64.zip`，比较 `tag_name` 和当前版本。
3. 弹窗展示版本、更新说明；用户可稍后。
4. 下载到 `%LOCALAPPDATA%\Loop\updates`，校验大小和 `digest`（如果有）。
5. 解压到 staging，检查 `version.json` 与 Release 版本一致。
6. 启动 PowerShell 助手，退出应用；助手等待旧进程结束，备份、覆盖程序文件、重启。
7. 覆盖时保留 `data/loop.db`、`data/files` 等用户数据。

## 测试

- 设置页「检查更新」使用真实 GitHub。
- 本地 mock：

```bat
set LOOP_UPDATE_API=http://127.0.0.1:8766/releases/latest
release\Loop-Desktop\Loop.exe
```

mock 返回标准 GitHub Release JSON 即可，无需改代码。

单元测试：

```bat
cd app
..\.tools\flutter\bin\flutter test
```

覆盖语义版本比较、Release 附件选择、下载 SHA-256、解压校验和用户数据排除。

## 限制

- 当前环境访问 GitHub 被 DNS/网络策略拦截，**真实 Release 端到端检查未在本机验证**；已用本地 mock 验证启动弹窗、下载、解压和助手替换。
- 没有代码签名；自动更新依赖 GitHub HTTPS + SHA-256 + `version.json` 校验。若需要更高安全性，应给 exe 做代码签名。
- 仅支持便携目录；如果 Loop 放在 `Program Files` 且当前用户无写权限，会提示手动下载覆盖。
- PowerShell 助手可能被杀毒软件拦截；失败会回滚到旧版本并写 `%LOCALAPPDATA%\Loop\updates\update.log`。
- GitHub 被墙时检查会超时/报错，设置页保留「手动下载 / Release 页面」入口。
